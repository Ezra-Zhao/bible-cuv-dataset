# 来源与审计记录（Provenance）

本文件记录本数据集的底本来源、版本锁定、审计过程与校验方法。
维护者请注意文末红线：防止后续版本「顺手对齐成新标点」而污染底本。

## 一、底本与锁定

- **底本定性**：1919 年官话和合本译文，圣经公会通行电子本字形
  （定性依据见第三节审计结论；公开口径见 README 与 DEVIATIONS.md）。
- **数字来源**：FHL（信望爱）OfflineBible 谱系。直接取用文件为
  xuan9/ChineseBibleSearchJS 仓的 `bibleText.js`（文件头自述
  "The bible text is from: http://springbible.fhl.net/OfflineBible/offline.html"），
  并以 FHL 官网 API（version=unv）抽样逐节比对同文。
- **版本锁定**：
  - 仓 commit：`1034aee964b8b7604a1daba6aafbd1c25cdac815`
  - `bibleText.js` SHA-256：`81f3cd19320888beb5742ebb5509c4d4d39cba64c2ab6c52eeb8de48fc682a6f`
  - 解析转储 SHA-256：`f71f8d20507d63b7d159023f28bbd73b85d698d6c216d30d11f67dfa6de26219`
  - 锁定验证：自 `bibleText.js` 重新抽取的 31,103 行与解析转储逐行一致，
    解析零异常（`scripts/parse_a.py` 可复现）。

## 二、候选源审计（2026-10-29，P0 阶段）

| 谱系 | 结论 |
|---|---|
| A · FHL 谱系（本底本） | 人名层无新标点特征（流便×90／呂便×0、士班雅×2／西班牙×0）；字形层四项系统性现代化（见 DEVIATIONS.md）。定性为「1919 译文·公会电子本字形」 |
| B · 数据库文件谱系（两仓同文件） | **弃用**：检出新标点人名指纹「西班牙」×2（罗 15:24、15:28），另有女性代词「她」由 17 处扩写至 1,514 处、旧式夹注被改写成现代句等二次编辑层；且与 A 同源，不构成独立交叉源 |
| C · mondain-dev/cuv-1919（印本排字工程） | 指纹全过（喫×65、纔×23 等），确立 1919 印本字形标尺；但仅含创世记 50 章，作标尺不当主源 |
| CrossWire ChiUnion 模块 | 官方分发路径在本项目网络环境不可达（多次 404），记为未核实，未取用 |

关键判断：市面流通的数字化和合本全文没有一份是 1919 印本逐字原貌；
本项目因此采用「如实改标」口径发布——称「1919 译文（圣经公会电子本字形）」，
与印本原貌的全部已知偏离写入 DEVIATIONS.md 公开，不冒称原貌。

## 三、许可分析

- 1919 年和合本译文：版权已经期满（public domain）。英文维基 CUV 词条
  信息框明载 "Copyright: Public domain (copyright expired)"；1919 年出版物
  在美国亦早入公版。
- 字形规范化（喫→吃 等）属字形层处理，不产生新的著作权客体。
- 1988 年新标点本（CUNPS）的标点、分段、人名修订是联合圣经公会／香港
  圣经公会的受版权编辑成果——**本数据零混入**，审计证据见上表人名层计数。
- 讲道／释经等内部工作线以新标点本作校对参照，与本数据集无关；
  其文本一字不得流入本数据。

## 四、生成与校验（全部可复现）

1. 生成：`scripts/build_dataset.py` 将底本逐节转为 JSONL；繁体为原文，
   简体为 OpenCC t2s 机械转换。
2. 逐章对账：`scripts/verify.py` 对 1,189 章逐章与公认分节参考表
   （独立 KJV 数字化 thiagobodruk/bible 之 en_kjv 逐章计数）比对——
   差异仅约翰三书第 1 章 1 处（15 vs 14 节，和合本分节，保留并登记）。
3. 全量逐字比对：生成数据每一节的 `text_trad` 与底本原文逐字比对，
   31,103 节全部一致（完整性检查内置于 verify.py，非抽样）；
   另留固定种子抽样 20 处记录于校验报告。
4. 对账总表：`scripts/reconcile.py` 产出 66 卷逐卷章／节对账与偏离计数。
5. 完整性：MANIFEST.json 与 SHA256SUMS.txt 随发布提供，下载后可一条命令
   验全量哈希。

## 五、红线（维护者必读）

- 新标点本（CUNPS／CUNPSS）只许作内部「对照镜」：发现底本某节与通行
  读本差异过大时提示人工复查。**其文本、标点、分段、人名修订一字不得
  进入本数据。**
- 不得把本数据回改成「更像印本」的重构字形后冒称原貌；字形层如需变动，
  必须先更新 DEVIATIONS.md 并升版本号。
- 勘误走 issue → 校验脚本复跑 → 小版本（v1.x）发布，勘误记录进
  CHANGELOG，不静默改数据。
